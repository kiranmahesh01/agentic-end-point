Agentic Endpoint Security

Independent Execution Broker for AI Agents

The agent proposes. The broker decides.

The Problem

AI agents act under your identity. When compromised, they have your credentials.

Compromise is a sentence, not a binary.

Goal Hijacking

A prompt injection in processed data causes the agent to work for the attacker.

Tool Poisoning

A malicious tool definition loaded from a repository executes attacker code.

Credential Theft

Over-delegated credentials give attackers full account access.

Why Now?

  • Coding agents in every IDE writing and executing code
  • Browser extensions with full page access and API credentials
  • MCP servers exposing tools and resources locally
  • Skills and plugins extending agent capabilities
  • Local models processing sensitive enterprise data

All acting as the user. All inheriting credentials. All potential attack surfaces.

Why EDR Is Not Enough

EDR sees the user's process. EDR cannot see:

Agent Identity

Which specific agent performed this action?

Declared Goal

What was the agent trying to accomplish?

Input Trust

Was the input from a trusted or untrusted source?

Tool Integrity

Has the tool definition been modified?

Scope Boundaries

Is this action within the agent's approved permissions?

Task Context

What task is this action part of?

How an Action Is Mediated

  1. Agent calls broker.read_file("/workspace/data.txt")
  2. Broker canonicalizes path, checks for traversal
  3. Broker sends ActionRequest to PDP
  4. PDP queries Registry: is this agent known? active? approved?
  5. PDP checks permissions: can this agent read this path?
  6. PDP checks input trust: was input trusted?
  7. PDP returns: ALLOW / DENY / REQUIRE_APPROVAL
  8. Broker executes or returns error
  9. Telemetry records decision

Decision Outcomes

Decision Meaning Action
ALLOW Action permitted Execute the action
DENY Action forbidden Reject immediately
REQUIRE_APPROVAL Human approval needed Wait for approval
ALLOW_IN_SANDBOX Permitted in isolation Execute in sandbox
ISSUE_CREDENTIAL Scoped token needed Provide limited token
TERMINATE Emergency stop Kill switch activated

Data Safety

No Long-Lived Secrets

Tokens expire in 5 minutes. No PAT passthrough. Scoped to task and intent.

Default-Deny Egress

Network access requires explicit allowlist entry. All other egress blocked.

Input Provenance

Trusted vs. untrusted input labeled. Untrusted + exec = DENY.

Redacted Telemetry

Secrets, API keys, and chain-of-thought never logged.

Kill Switch

Not a polite stop. A hard kill. Order matters.

  1. Suspend component in registry (new actions fail)
  2. Revoke all tokens for agent (credentials invalid)
  3. Terminate task tree in broker (in-flight work stops)
  4. Hook EDR isolate (endpoint isolated)
  5. Hook egress deny (network blocked)

The kill switch does NOT send "please stop" to the agent.
